# SEC-001 — First executable provider findings (2026-11-15)

**Scope:** GitHub Actions, synthetic credentials and disposable containers. **Result:** real OpenBao narrow-permission smoke PASS; real self-hosted Infisical **startup only** PASS; overall selection **DEFER**.

## Reproducible evidence

[GitHub Actions workflow run #43706252782](https://github.com/blondahouse/missLea/actions/runs/43706252782) completed successfully on the PR candidate revision `c8bfe3d9c5dd4195a0386e4e10e72b6dc8b2f54a`:

| Candidate | Tested service | Observed outcome | Evidence does NOT establish |
| --- | --- | --- | --- |
| OpenBao | Official image `ghcr.io/openbao/openbao:2.7.2`, temporary dev server, actual KV-v2 and policy/token APIs | **PASS:** read allowed only on expected canary path; forbidden write/system/token issuance blocked; revoked machine token denied | Real Broker/LLM separation, production auth method, unseal/recovery, stable storage or S8/S9 |
| Infisical | `infisical/infisical:v0.167.10` with PostgreSQL 16 + Redis 7, actual `GET /api/status` | **PASS (health only):** service reached HTTP 200 without real accounts | Any vault read/write, machine identity, access policy, revoke, recovery, S1–S9 |

The trial is **not** a comparable test of production security: one candidate was exercised through scoped APIs, the other only through startup. This asymmetry is recorded rather than hidden. Successful Actions jobs do not authorize production secrets.

**Documentary free-tier finding:** [official Infisical pricing](https://infisical.com/pricing) lists 5 identities in Cloud Free, while Access Controls, Secret Rotation and 30-day audit retention are in Pro. Infisical Cloud Free thus requires **independent Broker policy/audit** to potentially fulfill SEC-001 gates. A self-hosted free edition is a distinct topology and cannot inherit claims from the hosted Free plan.

## Mandatory gates — current assessment

| Criteria | OpenBao isolated dev test | Infisical self-host test |
| --- | --- | --- |
| S1 LLM never sees raw secrets | NOT TESTED (no LLM/Broker) | NOT TESTED |
| S2 independent service identity | PARTIAL: token with limited policy; production auth NOT TESTED | NOT TESTED |
| S3 operation scope + budget + revoke | PARTIAL: KV scope and revocation pass; budgets/Broker NOT TESTED | NOT TESTED |
| S4 independent unlock and recovery | NOT TESTED | NOT TESTED |
| S5 no unavoidable paid subscription | Local test runs on CI without vendor signup; real Demo hosting cost NOT TESTED | Local test on CI without vendor signup; real Demo hosting cost NOT TESTED |
| S6 durable sanitized audit | NOT TESTED (only sanitized CI evidence) | NOT TESTED |
| S7 portability and authority ownership | NOT TESTED | NOT TESTED |
| S8 stale-grant fencing and clone safety | NOT TESTED | NOT TESTED |
| S9 Broker protected from agent code deployment | NOT TESTED | NOT TESTED |

**Decision:** DEFER. Do not award a winner on unequal evidence or grant either product a real Cloudflare management key. Next minimally valuable test is a **separately authenticated Broker using a candidate's real machine identity** with one allowed operation, one denied arbitrary operation, safe revocation, and a second-host restore/fencing scenario, without a shared deployment privilege.

Security note: OpenBao **dev mode is intentionally insecure and memory-only**, and never a valid deployed vault. All test credentials are generated inside ephemeral CI and not published.
