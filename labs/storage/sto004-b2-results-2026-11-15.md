## Strict interpretation

**Demonstrated:** a real external object-storage provider accepts a restic-encrypted archive and serves it for precise restoration on a clean cloud runner, with the agent remaining inactive. This advances practical evidence for STO-001 D3 and aspects of D1/D6/D8.

**Not demonstrated:** independence from Backblaze as a single storage provider (D4); provider-admin deletion resistance, immutable retained generations and independent writer/reader credentials (D5); secure independent root-key escrow; a stable zero-subscription-cost configuration under actual recurring usage (D7); measured long-term RPO/RTO; automatic identity fencing.

The test-only restic password is intentionally public in the workflow: **the synthetic archive offers no actual confidentiality** even though restic encryption worked. Real memory must never use that password or this manual GitHub environment mechanism as a production Credential Broker. Only the temporary bucket-scoped B2 access key was private.

The workflow leaves a **small synthetic test repository** in `misslea-storage-lab-b2/sto004/43764709976/` for subsequent independent-provider comparison. Its content is test-only and can be deleted later after explicit retention decisions. Backblaze test credentials must be revoked after the authorized integration experiments, no later than their defined expiry.
